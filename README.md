# 开票雷达 · GitHub 独立版

入口： https://z2vn7g8nhp-beep.github.io/polaris-isolated-lab-20261113/

网页由 GitHub Pages 提供，后台由 GitHub Actions 直接检查西安 MOMOPARK UME、荟聚寰映的猫眼排片。运行与日常使用均不请求 ChatGPT Sites，也不需要登录 ChatGPT。

## 使用

1. iPhone：用 Safari 打开上面的 Pages 地址，分享 → 添加到主屏幕，再从桌面图标打开。需要 iOS 16.4 以上。电脑可直接打开网页。
2. 在「监测与推送」连接一次只限本仓库的 GitHub Fine-grained token：Repository access 选择本仓库，Contents 和 Actions 设为 Read and write。
3. 点「启用手机通知」，允许系统通知，再点「发送测试通知」。后台执行后会向最近启用的这台设备发送测试；请以手机实收为准。
4. 在片库点击 ☆ 星标电影。Bark 是可选的，不需要填写即可使用系统通知。

配置和手动检查通过 Actions 执行，通常需要一两分钟。后台计划每 5 分钟触发，GitHub 高峰时可能延迟。关闭网页后仍继续检查和发送通知。系统通知显示、声音和延迟受设备设置及网络影响。

当前已实际观察到 GitHub cron 有 52～72 分钟的触发间隔，原生定时不能保证五分钟盯票。页面超过 15 分钟未成功检查会明确提示延迟；以实际成功检查时间为准。[外部定时触发的可选配置](SCHEDULER.md)可用于改善准时性。

「猫眼待映」以猫眼 comingList 的 movieIds 为分类依据，展示最受期待和按上映日期分组的列表；未来上映日期本身不再等于待映列表成员。待映名单约每 30 分钟同步，热映名单约每 2 小时同步；想看人数和电影资料每轮至多更新 12 部，目标以当前约 185 部的片库每 1～2 小时覆盖一轮。名单与资料分别计时；影院排片更新不算作想看人数刷新。保留已收录电影和星标。

同一电影在正式上映前，能观测到的新场次、明确不可售后恢复可售、可识别批次变化都会再次提醒。同一状态不重复，星标直到手动停止。两轮之间发生又结束的变化无法保证看见。

手机通知订阅已加密存储；过期订阅会失效提示，未发提醒保留。重新启用通知后继续处理，不自动切换到 Bark。一次只向最近启用的设备发送。

每次正常检查至多请求猫眼 4 次：两家影院、至多一份名单、至多一批资料，全程串行。手动检查仍受冷却限制；网络失败会退避，遇到验证、403 或 429 会暂停，不会绕过。以上频率是计划目标，GitHub 调度延迟和退避可能使实际更新更慢。

## 数据与隐私

- `main`：网页、代码、公开的电影信息和 RSA 公钥。
- `preferences`：浏览器用 AES-GCM 加密的星标、手机通知订阅和可选 Bark 配置；AES 密钥再用 RSA-OAEP 封装给后台。
- `monitor-state`：加密的 SQLite 状态、加密的个人提醒记录，以及公开的片库快照。这个生成分支每轮覆盖，不累积完整数据库历史。
- GitHub token 只存在当前浏览器，不上传到仓库或后台；其派生密钥用于解密个人配置。因此跨设备使用同一个 token。更新或撤销 token 前，请保留旧 token，以便先解密迁移配置。
- Bark Key 在公开仓库中只以密文出现。监测到验证码、限流或访问限制会暂停，需本人在页面手动恢复。

后台沿用 Repository Secret `WATCH_SITE_TOKEN` 作为加密主密钥，仅为兼容已完成的配置；它不再用于访问旧站。不要修改这个 Secret，否则现有状态无法解密。`WATCH_SITE_URL` 已不使用。

## 验证与部署

```sh
node --test tests/*.test.mjs
```

`.github/workflows/scheduled-watch.yml` 负责检查、保存状态和发布 Pages。`.github/workflows/test.yml` 运行监测与加密回归测试。

初始片库来自原 Sites 项目的 185 部电影，旧项目源码和旧仓库未修改。旧项目的参考目录不会推送。

GitHub Pages 和 GitHub API 的实际访问情况取决于本地网络；改用 GitHub 不能保证任何网络下都可达。
