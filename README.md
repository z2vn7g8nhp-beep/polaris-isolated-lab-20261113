# 开票雷达 · GitHub 独立版

入口： https://z2vn7g8nhp-beep.github.io/polaris-isolated-lab-20261113/

网页由 GitHub Pages 提供，后台由 GitHub Actions 直接检查西安 MOMOPARK UME、荟聚寰映的猫眼排片。运行与日常使用均不请求 ChatGPT Sites，也不需要登录 ChatGPT。

## 使用

1. iPhone：用 Safari 打开上面的 Pages 地址，分享 → 添加到主屏幕，再从桌面图标打开。需要 iOS 16.4 以上。电脑可直接打开网页。
2. 在「监测与推送」连接一次只限本仓库的 GitHub Fine-grained token：Repository access 选择本仓库，Contents 和 Actions 设为 Read and write。
3. 点「启用手机通知」，允许系统通知，再点「发送测试通知」。后台执行后会向当前这台设备发送测试；请以手机实收为准。
4. 在片库点击 ☆ 星标电影。Bark 是可选的，不需要填写即可使用系统通知。

配置和手动检查通过 Actions 执行，通常需要一两分钟。配置外部定时服务后，目标每 2 分钟检查两家影院；GitHub 原生每 5 分钟计划保留兜底，任务启动仍可能延迟。关闭网页后仍继续检查和发送通知。系统通知显示、声音和延迟受设备设置及网络影响。

当前已实际观察到 GitHub cron 有 52～72 分钟的触发间隔，原生定时不能保证五分钟盯票。页面在 6 分钟未成功检查时提示延迟；以实际成功检查时间为准。[外部两分钟定时触发配置](SCHEDULER.md)可用于改善准时性。

「猫眼待映」以猫眼 comingList 的 movieIds 为分类依据，展示最受期待和按上映日期分组的列表；未来上映日期本身不再等于待映列表成员。待映名单、热映名单、想看人数和电影资料以每 5 分钟整轮同步为目标。两分钟触发存在时间取整，正常情况下整轮间隔可能约 4～6 分钟；任务延迟或退避时更慢。每轮包含所有已收录电影和新名单中的 ID，按接口每批 12 部串行读取；影院排片更新不冒充资料刷新。保留已收录电影和星标。

同一电影在正式上映前，能观测到的新场次、明确不可售后恢复可售、可识别批次变化都会再次提醒。同一状态不重复，星标直到手动停止。两轮之间发生又结束的变化无法保证看见。

手机通知订阅已加密存储；过期订阅会失效提示，未发提醒保留。重新启用通知后继续处理，不自动切换到 Bark。支持多设备接收和独立管理；旧单设备订阅继续兼容。

开票轮询通常只请求两家影院；五分钟片库更新轮次另有至多 20 次资料请求，每批之间至少间隔 1 秒，全程串行。资料任务有 75 秒时间预算，未完成批次保留进度到下一轮。影院请求最短间隔 110 秒，为两分钟目标预留 10 秒任务启动偏差；手动检查和重复触发共用冷却。网络失败会退避，遇到验证、403 或 429 会暂停，不会绕过。以上频率是计划目标，GitHub 调度延迟和退避可能使实际更新更慢。

首页先显示本机缓存或公开片库，再并行同步 GitHub 中的最新片库、星标和提醒。私人缓存只保存加密封装，断开连接会清除本机私人缓存。海报按展示尺寸请求缩略图。缓存不会改变真实成功检查时间。

## 数据与隐私

- `main`：网页、代码、公开的电影信息和 RSA 公钥。
- `preferences`：浏览器用 AES-GCM 加密的星标、手机通知订阅和可选 Bark 配置；AES 密钥再用 RSA-OAEP 封装给后台。
- `monitor-state`：加密的 SQLite 状态、加密的个人提醒记录，以及公开的片库快照。这个生成分支每轮覆盖，不累积完整数据库历史。
- GitHub token 只存在当前浏览器，不上传到仓库或后台；其派生密钥用于解密个人配置。因此跨设备使用同一个 token。更新或撤销 token 前，请保留旧 token，以便先解密迁移配置。
- Bark Key 在公开仓库中只以密文出现。监测到验证码、限流或访问限制会暂停，需本人在页面手动恢复。

后台沿用 Repository Secret `WATCH_SITE_TOKEN` 作为加密主密钥，仅为兼容已完成的配置；它不再用于访问旧站。不要修改这个 Secret，否则现有状态无法解密。`WATCH_SITE_URL` 已不使用。

## 电影手记功能

首页保留纸感与酒红配色，使用紧凑的上映倒计时、日期时间轴和两行片名。月份、排序与上映日历位于「筛选」中；电影详情先展示海报与影院场次，点击「提醒规则」展开编辑。设置页将连接和通知分步展示，密钥迁移与 Bark 位于「高级设置」。自动更新时会保留展开状态和正在填写的表单。

页面内的自动刷新合并更新，并复用已有场次、记录与表单控件；搜索草稿、批量模板选择和多选电影会保留。个人手记、普通观影记录和模板的保存只做加密同步，不额外启动影院检查或 Pages 发布；星标、实际提醒规则、通知偏好以及明确选择「同时暂停提醒」仍会触发后台处理。个人同步版本与监测配置版本分别跟踪，纯手记保存不会显示为监测配置待应用。

编辑详情时，影院场次继续局部更新；保存请求期间继续输入的内容会保留为未提交草稿，同一表单不会重复提交。断开或更换连接会关闭并清空私人编辑弹窗、撤销记录与临时倒计时选择。已读、实收确认和倒计时选择也只加密同步，不额外启动监测。手机通知区按本机登记状态显示启用、测试和停用操作。

### 场次、观影记录与提醒偏好

- 「场次总览」跨电影查看今天、明天、本周末或全部未来场次，可按影院、影厅、星标和个人规则筛选。复用已有排片快照，不增加猫眼请求；界面显示实际观测时间。
- 在场次或电影详情里「记录已购票」，可填写影院、日期、时间、影厅，并选择同时暂停该片开票提醒。记录仅表示本人手动登记，不会下单或读取猫眼订单。之后可标为已看，也可直接「记一次观影」。观影次数由已看记录累计，删除记录时同步调整。
- 已有购票和观影记录均可编辑；编辑保留原记录和日历 UID。删除成功后 12 秒内可撤销，恢复记录也会恢复相应观影次数；撤销信息仅保存在当前页面内存中，断开连接时清除。其他设备已修改同一记录时，撤销不会覆盖新版内容。
- 「我的手记」集中展示购票、观影、标签和短评，支持按标签和片名／短评筛选。每部最多 12 个标签、100 条记录与 2000 字短评；个人配置加密后保存在 preferences 分支，不出现在公开片库。
- 购票记录可导出 `.ics` 文件，在手机或电脑日历中确认添加。默认预计片长 120 分钟，可在导出前调整；可选择提前 15、30、60 或 120 分钟提醒。时间以北京时间输入，以 UTC 写入日历，跨日场次正常处理。是否显示提醒由系统日历设置决定。
- 内置「工作日晚上」「周末 IMAX」「只看 IMAX」模板。电影详情可将当前规则另存为模板；设置页可批量应用，默认只填充未设置规则的电影。默认模板只作用于以后新增且没有单独规则的星标，不覆盖既有规则。
- 星标电影的完整上映日期发生变更，或从档期待定变为明确日期，会新增定档／改档记录并按通知偏好推送。首轮资料作为基线，不补发旧变化；空白或不完整日期不会抹掉已知完整日期。片库更新仍沿用现有请求频率。
- 普通电影可保持即时通知，或按 15／30／60 分钟窗口汇总。每部规则可设为重点电影，跳过汇总等待。免打扰默认关闭；开启后可选择是否允许重点电影和监测告警例外。后台发送前重新检查星标、规则、未来时间与已观测可售状态，失效开票消息取消；多设备汇总重试保留逐条接收回执。
- 独立的 `.github/workflows/watchdog.yml` 约每 10 分钟检查保存的成功时间，默认阈值为 15 分钟，可改为 30／60 分钟或关闭。一次失联通知成功交给推送服务后不重复，检查恢复后再通知一次；失败按设备保留回执后重试。手动暂停时不发失联告警。该工作流独立于原监测任务，但仍依赖 GitHub Actions 的可用性与调度；GitHub 整体不可用时无法保证及时告警。

独立检查记录超过 20 分钟未更新时，设置页明确显示过期状态。现有外部定时入口每次触发主工作流时，其 keepalive 作业会独立检查 watchdog 是否需要补触发；记录超过 10 分钟且没有排队或运行中的独立检查时才分派，不依赖影院检查作业成功。恢复通知按收到失联告警的设备分别补齐，未收到原告警的新设备不会收到无关的恢复通知；重试跳过已接收设备。

独立检查只读取已有快照与加密偏好，不请求猫眼；去重状态单独加密保存于可覆盖的 watchdog-state 分支。其 public.json 仅含检查时间、健康状态和告警是否交给推送服务，不含星标、手记、规则、设备或密钥。尚未连接通知渠道时不会发送告警。

首次监测始终失败时，失败任务写入的心跳不会延后独立告警；失联期间新启用通知渠道也能收到对应的恢复消息。排队通知发送前重新匹配最新观测到的场次时间、影厅及个人规则；关闭改档提醒后，不发送仍在排队的改档消息。

- 点击海报或片名查看详情、主演、评分、上映倒计时和两家影院的未来场次。场次复用现有影院检查，不增加抓取次数；显示观测时间，购票链接打开猫眼，余票和价格以猫眼为准。
- 「未来七天／本月上映／档期待定」、月份、热度和评分排序可组合使用。上映日历按北京时间显示正式上映日，点击日期筛选；可复制单部电影的分享链接。
- 每部电影详情可设置影院、制式或影厅关键词、星期、日期和时段。留空表示不限，多个制式关键词任一匹配，跨午夜时段受支持。默认只提醒上映前开票；填写「上映后继续监测至」可延长。可单独暂停提醒而保留星标。规则保存后由下一轮后台应用，不补发历史事件。
- 星标即时反馈，区分保存中、后台待应用和已应用；失败会回滚并提供重试。浏览分类、搜索、排序和视图切换时保留浏览状态。
- 提醒可筛选电影、未读或发送状态，标为已读；可合并同电影、同影院、两分钟时间窗内的同状态提醒。通知定位对应记录，记录提供电影详情和猫眼购票入口。旧提醒没有场次元数据时仍可通过电影详情查看场次。
- 「监测健康」分别显示影院检查时间、最近 24 小时的已记录检查结果、最长成功间隔、失败／暂停信息与下次允许请求时间。历史从本版上线后积累，未启动的任务不会产生记录。
- 通知支持最多 8 台设备。在每台设备中用同一 GitHub 密钥连接，填写本机名称并启用通知；设备可单独测试、命名或移除。已成功接受某条通知的设备不会因其他设备重试而重复发送；失效设备需重新启用。原有单设备订阅继续兼容。
- 首次使用清单引导完成连接、通知、实际收件确认和星标。测试区分「推送服务已接受」与用户手动确认的「手机实际收到」，不把服务返回成功当作实收证明。
- 「更换密钥，迁移配置」先用旧密钥解密，再用有本仓库 Contents / Actions 读写权限的新密钥重新加密。保留星标、提醒规则、通知设备和已读记录。旧密钥即使已过期，只要保留其字符串也可迁移；解密失败不会覆盖配置。其他设备之后必须使用新密钥重新连接。

规则、设备、已读和实收确认仍只存于加密的私人配置。公开片库新增的场次快照和健康记录不包含个人星标、规则或设备订阅。

首页「上映倒计时」可通过「更换电影」搜索片名或主演，也可只看星标。已连接 GitHub 时，所选电影随私人配置加密同步；未连接或同步失败时，当前页面仍可预览选择，同步失败会提供重试。倒计时以北京时间的上映日零点为目标，不代表具体场次开场时间；档期待定和已上映电影分别显示对应状态。

## 关闭 App 后的系统通知

推送消息同时包含传统字段与声明式 Web Push 内容。支持该能力的 Safari／iOS（WebKit 文档列明 iOS 18.4 起）可在后台脚本未能显示通知时使用系统兜底；旧浏览器继续由 Service Worker 调用 showNotification。推送处理不读取页面登录信息、不请求额外网络数据，也不要求有打开的 App 窗口。消息格式依据 [WebKit：Meet Declarative Web Push](https://webkit.org/blog/16535/meet-declarative-web-push/)。

网页的「测试请求已提交」、后台的「推送服务已接收」和手机实际显示通知是三个不同阶段。关闭或上划 App 后是否实收仍需在目标 iPhone 上验证，不能仅以服务端成功响应断言手机已收到。等待提交确认后再离开 App，可避免在请求尚未保存时中断；后台处理时间受 GitHub 排队影响。
